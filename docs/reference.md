# catenae reference {#mainpage}

What each public header promises, read from the headers themselves. Each contract point is a
requirement with an identifier, and every identifier is collected on the
[requirements page](req.html), where the test that pins it can be found by name.

The contracts a type of yours meets, their members documented once:

- @ref stage_contract
- @ref chain_contract
- @ref junction_contract
- @ref mailbox_contract
- @ref analyzer_contract

How they are written down is @ref conventions, in the words of the @ref glossary. What the
library assumes of its integrator is the register of @ref assumptions, and what knowingly
departs from the rules it is written to is the @ref deviations.

The guide, which explains why the library is shaped this way and how to use it, is at the
[top of this site](../index.html).
